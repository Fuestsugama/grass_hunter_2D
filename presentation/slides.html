Design choices

Simple OOP: each mechanism is used only where it brings something

Grass Hunter
Inheritance

Player and Enemy extend Entity: movement, collisions and the hit flicker are written once.

class Player(Entity): ...
class Enemy(Entity): ...
# move(), collision(), flicker()
# come from Entity
Polymorphism

One call updates every sprite; each class answers in its own way.

self.visible_sprites.update()
# Player.update()   reads keys
# Enemy.update()    chases
# ParticleEffect.update() plays
Composition

Level is built from parts it owns and drives every frame.

self.ui = UI()
self.upgrade = Upgrade(self.player)
self.magic_player = MagicPlayer(
    self.animation_player)
Callbacks

Enemies receive the Level methods they need: no import of Level, low coupling.

Enemy(name, pos, groups, obstacles,
      self.damage_player,
      self.trigger_death_particles,
      self.add_exp)
Data-driven

A new monster is one entry in settings.py, placed on the map in Tiled.

'flam': {'health': 90, 'exp': 100,
  'damage': 30, 'speed': 3,
  'attack_type': 'fireball',
  'death_effect': 'spirit_explosion'}
Groups as roles

A sprite's groups say what it does; collisions are one call per role.

visible_sprites     # drawn
obstacle_sprites    # block moves
attack_sprites      # weapon, flames
attackable_sprites  # grass, enemies
02 · Architecture3 min
The six design choices. Inheritance only where it removes duplication (Entity). Polymorphism through pygame groups. Composition around Level. Callbacks keep enemies independent of Level. Content is data. Sprite groups describe roles.

Rules of play

The business rules: every number is a named setting in settings.py

Grass Hunter
Weapon hit
damage = attack + weapon

With the sword: 10 + 15 = 25. Each weapon has its own cooldown.

Spell hit
damage = magic + strength

Flame: 4 + 5 = 9, five times along a line.

After a hit
invulnerable 500 ms / 300 ms

Player / enemy. The sprite flickers; the enemy is pushed back by its resistance.

Energy
refill = 0.02 × magic

Per frame, up to the max. A spell costs 20 (flame) or 10 (heal); refused if not enough.

Upgrade
stat × 1.2 · cost × 1.4

Paid with XP, and the stat never goes above its max.

Death
health 0 → game over

XP is earned when a monster dies. At 0 health the world freezes; R restarts with fresh stats.

Problem

The same 5 lines made the sprite blink after a hit, copied at the end of Player.animate() and Enemy.animate().

Before / after 3

NAMES · CONSTANTS · BUG · The upgrade that went past its max

Grass Hunter

Problem

The cap check compared values but assigned nothing, so health could reach 358 / 300. Magic numbers 1.2 and 1.4, a long condition and a cryptic name.

Fix

Named conditions, the factors moved to settings.py, and min() caps the stat at its maximum.

358→300
max health after upgrades (max = 300)
BEFORE
upgrade.py · Item.trigger()
def trigger (self, player):
upgrade_attribute = list(player.stats.keys())[self.index]
 
if player.exp >= player.upgrade_cost[upgrade_attribute] and  player.stats[upgrade_attribute] < player.max_stats[upgrade_attribute]:
player.exp -= player.upgrade_cost[upgrade_attribute]
player.stats[upgrade_attribute] *= 1.2
player.upgrade_cost[upgrade_attribute] *= 1.4
 
if player.stats[upgrade_attribute] > player.max_stats[upgrade_attribute]:
player.stats[upgrade_attribute] > player.max_stats[upgrade_attribute]
AFTER
upgrade.py · Item.trigger()
def trigger(self, player):
"""Spend XP to raise the selected stat, never above its maximum."""
stat_name = list(player.stats.keys())[self.index]
cost = player.upgrade_cost[stat_name]
max_value = player.max_stats[stat_name]
has_enough_exp = player.exp >= cost
is_below_max = player.stats[stat_name] < max_value
if has_enough_exp and is_below_max:
player.exp -= cost
player.stats[stat_name] = min(player.stats[stat_name] * UPGRADE_STAT_FACTOR, max_value)
player.upgrade_cost[stat_name] *= UPGRADE_COST_FACTOR
settings.py
UPGRADE_STAT_FACTOR = 1.2
UPGRADE_COST_FACTOR = 1.4

A real bug found during the review: the cap line compared but did not assign, so health went past its max. The fix also names the conditions and moves the factors to settings. A test now guards this rule.

Before / after 4

OPTIMISATION · DRY · SRP · Load each sound once

Grass Hunter

Problem

Every enemy loaded and decoded its own 3 sounds: 39 enemies = 117 Sound objects. The same Sound() + set_volume() pair was repeated in 5 classes.

Fix

A small sound.py module caches each file: the first call loads it, the next calls reuse it.

117→5
sound objects for the 39 enemies
BEFORE
enemy.py · Enemy.__init__(), run for each of the 39 enemies
self.death_sound = pygame.mixer.Sound('../assets/audio/death.wav')
self.hit_sound = pygame.mixer.Sound('../assets/audio/hit.wav')
self.attack_sound = pygame.mixer.Sound(monster_info['attack_sound'])
self.death_sound.set_volume(0.2)
self.hit_sound.set_volume(0.2)
self.attack_sound.set_volume(0.25)
+ the same Sound() / set_volume() pair in Player, MagicPlayer, Level and Game
AFTER
sound.py · new module, the only place that loads audio
_loaded_sounds = {}
 
def load_sound(path, volume=1.0):
"""Load a sound the first time it is asked for, then reuse it."""
if path not in _loaded_sounds:
sound = pygame.mixer.Sound(path)
sound.set_volume(volume)
_loaded_sounds[path] = sound
return _loaded_sounds[path]
enemy.py · Enemy.__init__()
self.death_sound = load_sound('../assets/audio/death.ogg', 0.2)
self.hit_sound = load_sound('../assets/audio/hit.ogg', 0.2)
self.attack_sound = load_sound(monster_info['attack_sound'], 0.25)
04 · Clean Code and tests3 min
Optimisation: every enemy decoded the same sound files. Now sound.py loads each file once and shares it: 117 objects become 5, and only one module touches audio.
